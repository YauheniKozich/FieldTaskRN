# FieldTaskRN

Offline-first task planner for field employees, built as an Android-first React Native app.

## Features

- Create, edit, view, status-update, and delete field tasks. Completed and cancelled tasks remain visible.
- Required field validation, sorting, optional coordinates, image attachments, and an activity history.
- SQLite persistence for tasks, attachment metadata, history, and theme preference.
- Offline-first mutations with pending/synced/failed state and manual or reconnect-triggered sync.
- Local reminders, a 30-second demo action, task map markers, and System/Light/Dark theme selection.

## Technology

Expo SDK 57, React Native 0.86, TypeScript strict mode, Expo Router, Zustand, expo-sqlite, Zod, expo-image-picker, expo-file-system, expo-notifications, react-native-webview with locally bundled Leaflet 1.9.4 and OpenStreetMap Deutschland raster tiles, NetInfo, and json-server 0.17.4. SQLite is the durable source of truth. Repository methods keep screens clear of SQL. The mock server is pinned to json-server 0.17 because its POST endpoint preserves client-generated task IDs, which the sync protocol needs. Expo SDK 57 requires Node.js 22.13 or newer; the generated iOS project targets iOS 16.4 or newer.

## Install and run

```sh
npm install
npx expo install --check
npm run start
```

Run the mock server in another terminal:

```sh
npm run server
```

The Android emulator default is `http://10.0.2.2:3000` (the host machine's port 3000). For a physical Android device on the same Wi-Fi, change `API_URL` in `src/config/mockServer.ts` to the development computer's LAN IPv4 address, keep the server bound to `0.0.0.0`, and allow inbound port 3000 on the computer's firewall. `server/db.json` includes a sample task record.

## Android APK

An internal installable APK can be created with EAS Build:

```sh
npx eas-cli build --platform android --profile preview
```

The `preview` profile sets `android.buildType` to `apk`. EAS Build also requires an Expo account and project association on the first run. A local native build is available after Java and Android SDK setup with `npx expo run:android`. For a locally signed release APK, configure `FIELD_TASK_RELEASE_STORE_FILE`, `FIELD_TASK_RELEASE_STORE_PASSWORD`, `FIELD_TASK_RELEASE_KEY_ALIAS`, and `FIELD_TASK_RELEASE_KEY_PASSWORD` as private Gradle properties or environment variables before running Gradle's `assembleRelease` task. Without these values, the release variant is unsigned; it is never signed with the debug key.

## Architecture

`app/` contains Expo Router routes and tabs. Screens use the Zustand store for task operations; the store coordinates repositories, domain validation, and the synchronization feature. `src/domain/` contains task and sync rules with no React Native or persistence dependencies. `src/repositories/` exposes local application data operations backed by SQLite in `src/storage/`. `src/platform/` contains device adapters for attachments, location, and notifications. `src/data/remote/mockTaskApi.ts` handles HTTP and JSON-server mapping; `src/features/sync/syncCoordinator.ts` coordinates local data, network state, and remote synchronization. `src/theme/` owns theme selection and exposes colors to reusable UI components. `src/config/` holds app and mock-server configuration. The app does not require network access for task operations.

## Local data and offline behavior

SQLite is the source of truth. Task changes are committed locally with their history entry before the UI refreshes. Deletion writes a local `deletedAt` tombstone and hides the task immediately. Attachment files and metadata remain until the server confirms deletion, so a newer remote version can restore the task with its local attachments. During sync, the server receives `DELETE /tasks/:id`; the local tombstone and attachment files are purged only after a successful delete or confirmation that the server record is already absent. Sync runs on connectivity restoration and can be retried from Settings. Failed requests leave local rows intact and flag pending rows as failed. A task changed during sync is checked again inside the commit transaction and retried.

## Synchronization and conflict resolution

Sync reconciles IDs already present in local SQLite by reading `/tasks/:id`, then using `POST /tasks`, `PUT /tasks/:id`, or `DELETE /tasks/:id`. It does not import server-only records. For a matching active record, the later valid `updatedAt` wins; timestamps are UTC ISO strings generated by device clocks, and the local copy wins exact timestamp ties. A newer deletion wins by issuing `DELETE`; a newer remote active record can restore a locally tombstoned task. This is a small single-user mock, not a secure multi-user service; it does not exchange image binaries or their local URIs. Keep device clocks reasonably accurate and task IDs stable.

## Attachments

After saving a task, choose **Edit task → Add image**. Selected images are copied to the app's document directory and their URI, filename, MIME type, and task ID are saved in SQLite as one batch. If the batch fails, its copied files are removed and no metadata is committed. Missing files render an unavailable message rather than crashing. Removing an image deletes its SQLite metadata and attempts to remove its file. Images remain local and are not uploaded to json-server.

## Notifications

The app requests OS permission and schedules a real local notification 30 minutes before the due time. If that time has already passed because a task is due in under 30 minutes, it schedules a deterministic fallback for 30 seconds after save. Editing persists the task first, then cancels and reschedules its reminder. Sync also reconciles reminders when remote task details change. Failed reminder updates are reported separately from sync status; cancellation failures for purged tasks remain in a durable retry queue. Settings includes a clearly labeled real 30-second demo notification. Notification delivery is controlled by Android permissions and battery policy.

## Map and themes

Address is required; latitude and longitude are optional but must be provided together and within valid ranges. Tasks with coordinates appear as OpenStreetMap markers, whose callouts open task details. No geocoding API or map key is required. Leaflet code and marker images are bundled locally; map tiles still load online. Task editing and saved data remain available offline. The free OpenStreetMap Deutschland tile service is donation-funded and restricts commercial or high-traffic use. System, Light, and Dark preferences are stored locally. Run `npm run prepare-map` after changing the pinned Leaflet version to regenerate the checked-in map assets.

## Tests and validation

Run `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm test`, `npx expo-doctor`, and `npm audit --omit=dev`. The Jest suite covers validation, date parsing, reminder timing and reconciliation, retryable initialization, attachment cleanup, map HTML escaping, Router query parsing, and sync retries.

Expo Router 57 still requests CommonJS `query-string` 7, whose decoder dependency has no patched CommonJS release. The root `package.json` pins `decode-uri-component` to the fixed 0.5.0 release. During `npm install` or `npm ci`, `postinstall` applies the single import interop change in `scripts/patch-query-string.cjs`. It checks exact package versions and source text before writing, and fails if an upstream update needs review. Do not install with `--ignore-scripts`: Router query parsing depends on this patch. The `xcode` override pins its UUID helper to the fixed 11.1.1 release.

## Known limitations and trade-offs

- Map tiles require network access; without coordinates, tasks remain usable but do not have a marker.
- The mock API base URL is configured in source, and the emulator default needs changing for a physical device.
- Attachment binaries remain on the current device and are not synchronized.
- A production backend, authentication, multi-user conflict UX, and geocoding are outside assignment scope.
- Native Android build and notification behavior should be checked on a physical device or emulator with the target SDK and permissions.
